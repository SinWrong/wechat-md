# 文案 + 图片 → 公众号排版模板（Markdown）

两套入口，共用同一套排版规则：

| 入口 | 适合 | 启动 |
| --- | --- | --- |
| **桌面编辑器**（可视化） | 日常写稿、改稿、看效果 | 双击 `wechat_md_gui.bat` |
| 命令行 | 批量转换、接自动化 | `python tools/wechat_md.py 文案.md` |

`tools/wechat_md.py`：读入一篇文案（可带图片），解析出标题、导语、小节、正文、列表、引用、配图，按公众号阅读规范生成：

1. **一份 Markdown 模板**（主交付物）：带模板说明、排版参数表、可替换的正文结构、发布前自检清单；
2. **可选一份 HTML**：全部内联样式，浏览器打开全选复制，直接粘进公众号后台；
3. **可选一页预览**：375px 手机宽度，排版效果所见即所得。

---

## 0. 可视化编辑器（推荐日常用）

双击 `wechat_md_gui.bat`（或 `python tools/wechat_md_gui.py`），得到一屏三块：

```
┌───────────────────────────────────────────┬──────────────────┐
│ 标题输入框                                  │ 手机预览（375px） │
│ 工具条：B 标题 结论 配图 引用 列表 互动 关注 │ · 实时刷新        │
│ 文案编辑区（小标题/标记/加粗有高亮）          │ · 可调宽度        │
│                                            │ · 换主题即换色    │
└───────────────────────────────────────────┴──────────────────┘
   底部状态栏：字数 · 阅读时长 · 小节数 · 图片数
```

**能做哪些事**

- 写正文时右侧实时预览，所见即所得，不用来回切后台；
- **打开 / 导入**：`文件 → 打开…` 支持 md / txt / html / docx；`文件 → 从网页 / Word 导入…` 会直接把正文转成可编辑文案（打开 html/docx 时自动走转换，保存时默认另存为 .md，不覆盖原文件）；
- **批量转换**：`文件 → 批量转换…` 多选文件 + 选输出文件夹，一次生成全部 `_模板.md`；
- 工具条一键插入：加粗、小标题（自动编号）、结论卡、配图、引用、列表、互动提问、关注引导；
- **配图对话框**：选图 → 自动填 alt/图注 → 勾「复制到 imgs/」就把图片复制到文案旁边，换电脑也不丢；光标停在 `[IMG:...]` 行上再点「配图」= 编辑这张图，可改图注、可删除；
- 三种主题（商务蓝 / 新闻红 / 暖橙）随时切换，预览同步变色；
- **发布前体检**：自动查标题长度、结论卡、小节编号重复、图片路径不存在、图注缺失/占位、段落过长、分隔线过多、结尾组件，点条目直接跳到对应行；
- 导出 Markdown（带模板说明和自检清单）/ 导出可粘贴 HTML / 浏览器预览 / 复制 HTML 到剪贴板；
- 打开、保存、另存为，关窗/切换文件前提示未保存。

**快捷键**

| 键 | 作用 | 键 | 作用 |
| --- | --- | --- | --- |
| `Ctrl+S` | 保存 | `Ctrl+Shift+S` | 另存为 |
| `Ctrl+O` | 打开 | `Ctrl+N` | 新建 |
| `Ctrl+B` | 加粗 | `Ctrl+I` | 插入/编辑图片 |
| `Ctrl+1` | 小标题 | `Ctrl+2` | 结论卡 |
| `Ctrl+3` | 引用 | `Ctrl+4` | 列表 |
| `Ctrl+K` | 发布前体检 | `Ctrl+Z / Y` | 撤销 / 重做 |

> 预览里的图片是本地缩略图；导出 HTML 后，图片要在公众号后台重新上传一次（后台会过滤外链/本地路径）。

## 1. 快速开始（命令行）

```bash
# 最简：文案里的图片用 [IMG:路径] 标出来
python tools/wechat_md.py 文案.md -o 输出.md

# 同时生成可粘贴的 HTML
python tools/wechat_md.py 文案.md -o 输出.md --html 输出.html

# 图文分离：图片单独放文件夹，按文件名序号自动分配章节
python tools/wechat_md.py 文案.txt --images ./图 -o 输出.md

# 换主题 + 生成手机预览
python tools/wechat_md.py 文案.md --theme news --preview 预览.html

# 直接吃网页 / Word：公众号文章页、博客文章、docx 都行
python tools/wechat_md.py 文章.html -o 输出.md
python tools/wechat_md.py 稿子.docx -o 输出.md --summary

# 看支持哪些格式
python tools/wechat_md.py --list-formats
```

Windows 下也可以把文件拖到 `wechat_md.bat` 上，或命令行：`wechat_md.bat 文案.md --html 输出.html`。

依赖：**Python 3.8+，只用标准库**，无需 `pip install`。

## 2. 支持的输入格式

| 格式 | 扩展名 | 处理方式 |
| --- | --- | --- |
| Markdown / 纯文本 | `.md` `.markdown` `.txt` `.text` | 直接按模板语法解析；自动识别 UTF-8 / GBK / Big5 / BOM |
| 网页 | `.html` `.htm` `.xhtml` | 提取正文；**公众号文章页**只取 `#js_content`，自动跳过导航、工具条、隐藏块 |
| Word | `.docx` | 解析段落与标题样式，图片自动抽到同目录 `imgs/` |

### 2.1 HTML 是怎么读的

- **公众号文章页**（浏览器「另存为」或直接保存的链接页）：识别 `id="js_content"` / `rich_media_content`，
  只取正文容器；标题从 `og:title` / `<title>` 取，作者从 `<meta name="author">` 取，日期从 `var ct` 取；
  正文里的 `h1` 不会重复开小节。
- **普通网页**：优先 `<article>` / `<main>`，没有就用 `<body>`；`<h1>` 作标题，`<h2>`/`<h3>` 作小节。
- **统一规则**：`<p>` 分段、`<strong>` 转 `**加粗**`、`<blockquote>` 转引用、`<ul>/<ol>` 转列表、
  `<figure>` 的 `<figcaption>` 变成图片图注、`<img>` 的 `data-src`/`src` 变成 `[IMG:...]` 标记；
  `<script>/<style>/<nav>/<footer>/<form>` 和 `display:none` 的块直接丢掉。
- 标题里自带的「01 」「一、」会被剥掉，避免和小节编号重复。

### 2.2 Word 是怎么读的

- 按 Word 的标题样式（`heading 1~4`、中文「标题 1~4」）分小节，其余段落按顺序保留；
- 图片从 `word/media/` 抽出来，存到 docx 同目录的 `imgs/01.png`、`imgs/02.png`…，正文里自动插 `[IMG:imgs/01.png]`；
- 旧版 `.doc` 不支持，先在 Word 里「另存为 .docx」。

### 2.3 三个格式的实际效果

```
examples/wechat_article.html  → 公众号文章页（含隐藏块、导航、工具条，都会被过滤）
examples/blog_article.html    → 普通博客页（h1/h2、加粗、figure 图注）
examples/gbk_note.txt         → GBK 编码的 txt
examples/docx_demo/from_word.docx → Word（含一张图）
```

命令行加 `--from text|html|docx` 可以强制按某个格式解析（扩展名不规范、或内容伪装时用）。

## 3. 文案怎么写（三种元素混排都行）

```markdown
# 标题（一级标题 = 文章标题；没有就用第一行）

日期: 2026-10-16
作者: 张三

导语/首段。空行分段，同一段里的换行会自动合并。

## 01 小节标题        ← 也认 "01 xxx"、"一、xxx"、"## xxx"、"### xxx"
正文段落……

- 列表项一            ← 会输出成 ①②③
- 列表项二

> 专家原话或金句      ← 引用块

[IMG:图1.jpg|图片描述|图注说明|图源：某某]   ← 图片，后三段都可省
[IMG:./图/01.jpg]
[CTA]                ← 互动提问位（可省，省了会自动生成一句）
[END]                ← 关注引导位（可省）

## 写在最后           ← 识别为收尾段，不会当成普通小节
收束全文的一句话。
```

### 元素对照表

| 你写的 | 程序识别成 | 输出效果 |
| --- | --- | --- |
| `# 标题` | 文章标题 | 文首 `# 标题` + 元信息行 |
| `日期: / 作者: / 分类:` | 元信息 | 写进文首信息行 |
| `## 01 xxx` / `一、xxx` / `第 1 节` | 小节 | `## 01 xxx`，自动编号补零 |
| 空行分段的一行行文字 | 正文段 | 一段一行，保留全部文字 |
| `- xxx` / `1. xxx` | 列表 | `① ② ③ …` |
| `> xxx` | 引用 | `> xxx` 引用块 |
| `[IMG:...]` | 配图 | `![alt](路径)` + `> 图注` |
| `[CTA]` / `[END]` | 结尾组件 | 互动提问 / 关注引导 |
| `写在最后 / 结语 / 总结` | 收尾段 | 只出现一次，不参与编号 |

`[CTA]`、`[END]` 标记之后写的文字，会分别作为「互动提问」和「关注引导」的正文；只写标记不写文字时，用默认文案补齐。两个标记都可以省略。

图片标记 `[IMG:]` 的四段，用 `|` 分隔：

```
[IMG:路径|alt 文字|图注|图源]
```

- 只写 `路径`：图注留占位提示，提醒你补；
- 第三段里含「图源 / 来源 / 摄影 / 出处」：自动当图源处理，不和图注挤在一起。

## 4. 图片模式

**模式 A（推荐）**：在文案里用 `[IMG:...]` 精确控制每张图的位置和图注。

**模式 B**：图片单独放一个文件夹，`--images ./图`：

- 文件名以 `01-`、`02-` 开头的，自动分配给编号对应的小节；
- 其余图片按顺序均分给还没有配图的小节；
- 图注自动取文件名去掉序号和「封面/配图/截图/尺寸」等词后的部分，可再手改。

建议：正文配图统一 **16:9（1080×608）或 4:3（1080×810）**；竖版截图单独说明，不要通栏。

## 5. 参数

| 参数 | 说明 |
| --- | --- |
| `input` | 文案文件（md / txt / html / docx）；`-` 表示从标准输入读 |
| `-o, --out` | 输出路径，默认 `<输入名>_模板.md`；HTML 输入默认输出 `.html` 后缀，避免覆盖源文件 |
| `--html` | 同时输出可直接粘贴公众号的 `.html` |
| `--preview` | 输出手机宽度预览页（也是 HTML） |
| `--images` | 图片文件夹，按序号自动分配 |
| `--theme` | `business`（默认，商务蓝）/ `news`（新闻红）/ `warm`（暖橙） |
| `--title` | 覆盖标题 |
| `--from` | 强制输入格式：`text` / `html` / `docx`（默认按扩展名判断） |
| `--summary` | 强制生成「先说结论」卡片：从导语（或第一节）里取 3 个短句；填不满会自动截断——建议自己写 3 条更好 |
| `--no-cta` | 不生成互动提问 |
| `--no-end` | 不生成关注引导 |
| `--config` | 附加配置：`key: value` 文本或 JSON，可写 `标题` / `日期` / `摘要卡: 1` |
| `--list-formats` | 打印支持的输入格式后退出 |
| `--version` | 版本号 |

## 6. 输出长什么样

`输出.md` 的结构：

```
# 标题
<!-- 模板说明：主题 / 字数 / 阅读时长 / 排版规则 -->
> 日期 · 字数 · 阅读时长
> **先说结论**  · 结论一  · 结论二  · 结论三
## 01 小节标题
正文段 → 配图 → 图注
## 02 …
---
## 写在最后
**互动提问**
**关注「公众号名称」，每天一个新鲜事。**
---
## 附：排版规范（主题参数表）
## 附：发布前自检（10 条 checklist）
```

固定下来的规范（三套主题同理）：正文 16px / 行高 1.75 / 段后 16px / 不缩进左对齐；小标题 17px 加粗、只比正文大一档；图注 12px 灰色居中；分隔线最多 2 条；全文加粗 ≤ 5 处。

## 7. 从模板到发布

1. `python tools/wechat_md.py 文案.md --html 输出.html`
2. 浏览器打开 `输出.html` → 全选（`Ctrl+A`）→ 复制
3. 公众号后台新建图文 → 正文区粘贴 → 检查小标题竖条、卡片底色还在不在
4. 配图在微信编辑器里**重新上传**（HTML 里的本地图片路径会被后台忽略，属正常）
5. 手机预览，对照文末「自检清单」逐条过

> 选 Markdown 还是 HTML：`md` 用来改文案和存模板，`html` 用来一步到位贴进后台。两份是同一套参数生成的，不会打架。

## 9. 扩展

- **加主题**：在 `wechat_md.THEMES` 里加一组色值即可，命令行和编辑器都读这一处（编辑器另在 `gui_core.GUI_THEMES` 里登记名称与强调色）；
- **加组件**：`Block.kind` 是唯一扩展点，解析处标 kind、渲染处各写一个分支（md / html / 预览各一个）；
- **接自动化**：命令行的 `build()` 是纯函数式入口，可直接在别的脚本里调用；编辑器的 `gui_core` 不依赖 tkinter，也能单独复用（例如批量体检一批文案）。

## 10. 配套：让 AI 写「能直接导入」的文案

[`prompts/公众号文案生成提示词.md`](../prompts/公众号文案生成提示词.md) 是一份给大模型用的提示词，把本程序的语法写成契约，模型输出即可直接导入。

```bash
# 模型输出保存成 文案.md 后，先校验格式
python tools/check_prompt_output.py 文案.md

# 通过后直接生成模板
python tools/wechat_md.py 文案.md --summary
```

校验器会检查：标题写法与长度、结论卡 3 条、小节编号连续且不重复、段落 ≤90 字、加粗 ≤5 处、图片图注、分隔线 ≤2 条、`[CTA]`/`[END]`/`写在最后` 是否齐全。有问题会列出「必须修 / 建议改」，可以直接把结果贴回给模型让它改。
