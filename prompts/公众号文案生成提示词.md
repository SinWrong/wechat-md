# 公众号文案生成提示词（Markdown 版）

把下面「提示词正文」整段复制给任意大模型（DeepSeek / GPT / 豆包 / Kimi 都行），并把你想写的主题、素材、语气填进开头的 `【任务】` 里。模型会直接输出一份**本程序能解析、能排版**的 Markdown 文案。

生成后：保存为 `<主题>_文案.md` → 用 `wechat_md_gui.bat` 打开，或 `python tools/wechat_md.py <主题>_文案.md --summary`。
存成 `.md` 或 `.txt` 都行——程序的输入格式支持 **md / txt / html / docx**，纯文本会自动识别编码。

想先确认模型输出没跑偏，可以跑一下自带的校验器：

```bash
python tools/check_prompt_output.py 文案.md
```

## 提示词正文（从这里开始整段复制）

```text
你是一名公众号主编，帮我把下面的主题写成一篇「能直接导入排版程序」的公众号文案。
输出必须是纯 Markdown 文本，且严格符合我给的语法；不要解释、不要寒暄、不要额外说明。

【任务】
主题：{{在这里写主题，例如：秋冬换季，家里这 5 样东西该扔了}}
素材：{{把要点、数据、案例、链接粘在这里；没有就留空，由你补充常识性内容}}
账号定位：{{例如：民生资讯 / 职场干货 / 生活方式 / 母婴科普}}
目标读者：{{例如：25–45 岁城市上班族}}
语气：{{例如：像朋友聊天、克制、不煽情}}
篇幅：{{例如：1200 字左右}}
配图：{{例如：4 张，位置我来补；或：不需要图片}}

【硬性格式要求】
1. 全文只用下面这套语法，不要用表格、不要用 HTML、不要用脚注、不要用 emoji 当小标题。
2. 第一行是标题：`# 标题`，20–30 字，不加书名号，不出现「标题：」这类前缀。
3. 标题后空一行，接着写 3 条「先说结论」：
   ## 先说结论
   空一行
   > · 结论一（≤24 字）
   > · 结论二（≤24 字）
   > · 结论三（≤24 字，给读者一个可执行动作）
   空一行
4. 正文分 3–5 个小节，每个小节标题写成：`## 01 小节标题`
   - 编号用两位数字，从 01 开始连续递增；
   - 小节标题 ≤20 字，只写事实或悬念，不要用问号结尾；
   - 小节之间不要再写分隔线，程序会自动分栏留白。
5. 正文段落：
   - 一段一行，段落之间空一行；
   - 单段 ≤55 字（手机 3 行以内），超过就在分号、逗号或破折号处拆成两段；
   - 不要首行缩进（不要写全角空格），不要用两端对齐；
   - 全文加粗（`**文字**`）不超过 5 处，只加在「关键事实」或「结论」上，不加在整段上。
6. 需要列举时用无序列表：
   - 每条一句话
   - 不要嵌套列表
   程序会把它们排成 ①②③。
7. 需要引用专家原话、报告原文或金句时，用引用块：
   > 这里是一句引用，不超过 60 字。
8. 需要配图的位置，单独一行写图片标记；图注写清「谁 + 在做什么 + 证明了什么」：
   [IMG:图片文件名.jpg|一句话画面描述|图注：画面说明。图源：来源]
   没有图源就写「图源：待补」；不确定文件名时写 `图1.jpg`、`图2.jpg` 这样按顺序编号。
9. 结尾固定三件套，顺序不能变：
   ## 写在最后
   空一行
   一句收束全文的话（≤40 字，单独成段，可以加粗）
   空一行
   [CTA]
   一句互动提问（≤40 字，让读者愿意在评论区回答）
   [END]
   **关注「账号名」，一句话说明关注能得到什么。**
10. 不要出现：`## 01 01` 这种重复编号、`## 一、` 这种中文编号、没有编号的小节、超过 90 字的长段、连续两条 `---`、文末三段以上「求关注」。

【写作要求】
1. 开头第一段就进入场景或冲突，不要「随着……的发展」这类套话；
2. 每个小节只讲一件事，小节标题和内容必须对应；
3. 事实、数字、时间、地点要具体；不确定的信息不要编造，改成「据报道」或直接删掉；
4. 全文只保留 1 个核心观点，其余内容都服务于它；
5. 结尾不要重复正文，给一句能被单独转发的「金句」。

【输出格式】
只输出文章本身，从 `# 标题` 开始，到 `[END]` 的下一行结束。
用 ```markdown 代码块包住整篇文章，代码块外不要写任何字。
```

## 模型输出长什么样（示例）

````markdown
# 一头熊闯进加州人家，拉开冰箱吃了5小时，还专挑巧克力和焦糖糖浆

## 先说结论

> · 黑熊夜闯民宅，连开两台冰箱吃了 5 小时
> · 它专挑巧克力、焦糖糖浆这类高热量甜食
> · 遇到熊记住：别堵、别喂、给退路

家里冰箱要是忘了关，顶多化几块肉。可美国加州有一户人家，冰箱没等主人忘关，自己来了位"客人"——一头大黑熊。

## 01 一头熊，在别人家吃了 5 小时自助餐

夜色里，一头黑熊摸进厨房，人立起来，一只爪子搭住冰箱门，轻轻一拉——门开了，动作熟得像在自己家。

[IMG:01-监控.jpg|黑熊拉开冰箱门|图注：监控画面里，黑熊用前爪拉开冰箱门翻找食物。图源：待补]

屋主清点"损失"时发现，这熊不是随便乱吃，而是有明显的口味偏好——**尤其钟情巧克力和焦糖糖浆**。

## 03 好笑归好笑，屋主已经报了管理部门

> 野生动物专家提醒：住在野生动物活跃区附近的人，要加固房屋门窗，带有浓烈气味的食物一定妥善存放。

- 别堵：给它让出一条能离开的路
- 别喂：投喂只会让它下次还来
- 慢退：别大喊大叫，退到安全处再联系管理部门

## 写在最后

熊来不来是它的事，咱们先别给它留菜单。

[END]

## 语法速查（给模型看，也给你自己核对）

| 元素 | 写法 | 程序怎么处理 |
| --- | --- | --- |
| 标题 | `# 标题` | 文章标题；首行没有 `#` 也能识别 |
| 结论卡 | `## 先说结论` + 3 行 `> · 结论` | 排成顶部浅色卡片（编辑器自动；命令行加 `--summary`） |
| 小节 | `## 01 标题` | 左竖条 + 主色编号 + 加粗标题 |
| 正文 | 一段一行、空行分段 | 16px / 行高 1.75 / 段后 16px |
| 加粗 | `**文字**` | 深色加粗，全文 ≤5 处 |
| 列表 | `- 条目` | 排成 ① ② ③ |
| 引用 | `> 一句话` | 浅底 + 左侧细线引用块 |
| 图片 | `[IMG:路径|描述|图注|图源]` | 图片 + 灰色图注；后三段可省 |
| 互动 | `[CTA]` + 下一行写问题 | 文末互动提问 |
| 关注 | `[END]` + 下一行写引导 | 文末关注引导 |
| 收尾 | `## 写在最后` | 固定收尾段，不参与 01/02 编号 |
| 分隔线 | 不要写 | 正文里最多留 2 条，程序建议用间距分组 |

## 使用建议

1. **先给素材，再让模型写。** 提示词里「素材」越具体，成稿越少空话；没有素材时模型容易编数字，发布前务必核对。
2. **一次只生成一篇。** 让模型批量写 5 篇，格式遵守率会明显下降。
3. **拿到输出先自检。** 检查四件事：`# 标题` 在第一行、`## 01` 编号连续、没有超过 90 字的段落、`[CTA]`/`[END]` 各只有一处。
4. **改稿只改文字，不动标记。** `## 01`、`[IMG:...]`、`[CTA]`、`[END]` 是程序的锚点，删了或改错会掉版式。
5. **配图位置可以留空。** 模型写 `[IMG:图1.jpg|...]` 只是占位，你在编辑器里点「配图」换成真图即可，程序会保留图注。
6. **不同模型会有细微偏差。** 如果输出里出现 `## 01、`「一、」、`**整段加粗**`、emoji 小标题，直接把上面「硬性格式要求」再贴一次，多数模型会立刻收敛。
7. **长文分两次生成。** 超过 2000 字时，先让模型写 3 个小节，再让它「按同样格式续写第 4–6 节」，避免后半段格式漂移。

## 常见翻车与修法

| 翻车 | 表现 | 修法 |
| --- | --- | --- |
| 标题带标记 | `# 【标题】xxx`、`标题：xxx` | 让模型重出第一行；或手动删掉前缀 |
| 编号重复 | `## 01 01 xxx` | 程序会剥掉一层，仍重复就手动改 |
| 段落过长 | 一段 120 字 | 让模型「把第 3 段按句号拆成两段」 |
| 分隔线过多 | 每节之间 `---` | 全删，正文最多 2 条 |
| 图片标记漏图注 | `[IMG:a.jpg]` | 编辑器会提示「图片缺图注」，补一行 `> 图注` |
| emoji 当小标题 | `## 🐻 熊来了` | 要求「小标题不加 emoji」 |
| 文末三连关注 | 三段「点个关注」 | 只留 `[END]` 后一行 |

## 附：和程序版本对应关系

- 适用版本：`wechat_md` 1.1 / 编辑器 1.0（本仓库当前版本）；
- 支持的语法以 `tools/README.md` 第 3 章「文案怎么写」为准；
- 提示词里没写、但程序也认的写法：`## 一、xxx`、`第 1 节 xxx`、`## 标题`（无编号，程序自动补号）、`>` 多行引用、`- ` 与 `1. ` 列表——**但建议模型只用标准写法**，减少格式漂移。
