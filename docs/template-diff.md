# 两份模板对比：代码实现 vs 推荐效果

**对比对象**

| | A（外部文件） | B（本仓库样例） |
| --- | --- | --- |
| 路径 | `E:\savepath\素材\大促下单前…_模板.md` | `examples/bear_模板.md` |
| 来源 | 本程序（或同版式工具）生成 | 本程序生成 |
| 字数 | 779（模板自述）/ 实际正文约 640 | 652 |
| 小节 | 4 | 4 |

**先说结论**

两份模板的**版式骨架是一致的**（标题 → 结论卡 → `## 0N` 小节 → 插图 → 写在最后 → 互动 → 关注），差异集中在两处：

1. **内容层面的图注质量**：A 的图注是「文件名式标签」，B 的图注是「画面说明 + 图源」——这是 A 没按推荐规范写，不是程序问题；
2. **往返能力**：把这两份**生成物**重新喂回程序（在编辑器里打开、改一个字、再导出），原来的实现会**丢图、丢图注、把注释和附录当正文**。这是真 bug，本次已修。

修完之后，两份模板都能原样往返；剩下的差异只有 A 的文案本身需要补图注。

## 一、版式与内容对比

| 维度 | A 大促 | B 熊 | 结论 |
| --- | --- | --- | --- |
| 标题 | 20 字，悬念 + 数字感 | 31 字，略超 30 | A 合规，B 偏长（警告级） |
| 结论卡 | 3 条，都是"该怎么做" | 3 条，是"发生了什么" | 两种都对；新闻类用 B 式、攻略类用 A 式 |
| 小节标题 | 「价格这一关：先核到手价」——带冒号的"栏目名" | 「一头熊，在别人家吃了5小时自助餐」——事实句 | A 更像栏目，B 更像叙事；都不算错，但 A 的冒号在手机上容易读成半句 |
| 段落长度 | 最长 171 字（一段 6 行） | 最长 101 字 | A 明显超标，手机上一屏读不完 |
| 加粗 | 7 处 | 2 处 | A 超了「≤5 处」的自检线 |
| 列表 | 1 处（①②③ 写在正文里） | 1 处（`- ` 列表） | A 的 ①②③ 是纯文本，不是列表块，不会吃到 ①②③ 排版 |
| 引用 | 7 处，其中 2 处是「直播间识别」「定价补贴算法」这种**大纲标签** | 1 处，专家原话 | A 把写作时的栏目备注留在了正文里 |
| 图注 | 「> 直播间识别」「> 纠纷维权」——与图无关的短标签，无图源 | 「> 监控画面：…图源：凤凰网视频」——画面 + 来源 | **A 不合格**：图注没说明画面，也没有来源 |
| 图片路径 | `E:/imgs/01.png`、`E:/imgs/01-2.png` | 工作区内的真实路径 | A 的路径在别人机器上一定失效 |
| 结尾 | 金句 + 互动 + 关注各 1 次 | 同 | 一致 |
| 分隔线 | 2 条 | 2 条 | 都合规 |

**A 的图注问题具体是什么**

```markdown
![纠纷维权](E:/imgs/01.png)

> 纠纷维权
```

图注 = alt = 「纠纷维权」，四个字只说了主题，没说画面里有什么、也没标来源。按推荐规范应该是：

```markdown
![纠纷维权场景](E:/imgs/01.png)

> 图注：消费者在手机上核对订单与支付凭证。图源：某某平台截图
```

**A 的"大纲标签"问题**

正文里这两行：

```markdown
> 直播间识别
> 定价补贴算法
```

它们不是引用，是写稿时的栏目备注。渲染出来会变成两个孤立的引用块，读者会莫名其妙。发布前应该删掉。

## 二、把「生成物」再喂回程序：原来的实现会怎样

这是本次对比里**真正值得改代码**的部分。用原实现把 A、B 当作文案重新解析（模拟"在编辑器里打开模板、改一个字、再导出"）：

| 现象 | 原实现 | 修复后 |
| --- | --- | --- |
| 图片 | **0 张**（`![alt](path)` 不被识别，只认 `[IMG:…]`） | 2 / 3 张，全部还原 |
| 图注 | 变成 2 个**孤立引用块**（「监控画面…」浮在正文里） | 挂回对应图片 |
| 模板注释 | `<!-- 模板说明 -->` 被当成正文，渲染成 `&lt;!--` | 整段跳过 |
| 文末附录 | 「## 附：排版规范 / 发布前自检」被当成两个小节，**表格和清单全部进正文** | 整段裁掉 |
| 文首信息行 | `> 2026-10-01 · 全文约 652 字` 被当成引用块 | 跳过 |
| 加粗 | `**大促省下的钱…**` 星号原样输出 | 渲染成 `<strong>` |
| ①②③ 列表 | 三行被拼成一段 | 识别为列表，重新排成 ①②③ |
| 结论卡 | 无（`> **先说结论**` + 列表被拼成一段引用） | 还原成顶部卡片 |
| CTA / 关注 | 混在收尾段里 | `[CTA]` / `[END]` 各自归位 |

用数字说话（A 文件）：

```
修复前：小节 7（多了 <!--、-->、---）｜图 0｜HTML <img> 0｜附录残留 是
修复后：小节 4（干净）｜图 2｜HTML <img> 2｜附录残留 否
```

## 三、这次改了什么

### 1. 新增 `prepare_markdown()`：兼容"生成后的模板"

在 `parse_content()` 入口自动清洗，三种入口（命令行 / 编辑器 / 校验器）都生效：

- 剥掉 `<!-- … -->` 整段注释；
- 从「## 附：」起整段裁掉；
- `![alt](path)` + 下一行 `> 图注` → `[IMG:path|alt|图注]`；
- 文首 `> 日期 · 全文约 N 字` 信息行跳过（手写 `> 金句` 不受影响）；
- 老模板的 `**互动提问**` / `**关注「…」**` → 还原成 `[CTA]` / `[END]`；
- 裁掉文末残留的 `---`。

### 2. 解析器补三处

- **Markdown 图片**：`![alt](path)` 直接可用，不再只认 `[IMG:…]`；
- **①②③ 列表**：之前只认 `- ` / `1. `，现在 ①–⑩ 也算列表，重新导出时不会拼成一段；
- **结论卡**：`> **先说结论**` + 3 行 `> · 结论` 现在识别为 summary 卡（放文首），而不是一段引用。

### 3. 渲染器补一处

- 正文 / 引用 / 互动里的 `**加粗**` 现在输出 `<strong>`，不再原样输出星号。

### 4. 图注拆分更准

`图注：画面说明。图源：某处` 以前整条被当成 source、caption 丢掉；现在从「图源：」处拆开，前半句留给图注。

### 5. 测试

新增 `tests/test_roundtrip.py` 17 项，覆盖：生成 → 再解析的结构/图片/图注/结论卡/CTA/END 稳定性、二次往返不漂移、`prepare_markdown` 幂等性。当前 **57 项全部通过**。

## 四、推荐效果 vs A 的实际差距（内容侧）

程序只能保证"版式正确"，**图注和正文质量得写作者补**。A 要发之前建议改这 4 处：

1. **两张图的图注**：从「纠纷维权」「价格核对」改成「画面 + 来源」，例如
   `> 图注：消费者在手机上核对订单与支付凭证。图源：平台截图`；
2. **删掉两个大纲标签**：`> 直播间识别`、`> 定价补贴算法`；
3. **拆开 171 字的长段**：在「；」或「——」处断开，单段控制在 55 字内；
4. **加粗减到 5 处以内**：现在 7 处，重点会被稀释。

这些和程序无关，但正好是「发布前体检」（编辑器 `Ctrl+K`）会逐条报出来的问题。

---

## 五、一句话结论

- **A 和 B 的版式由同一套代码生成，骨架没有差别**；A 的瑕疵在图注、段落长度、加粗数量这些**内容规范**上，不在程序上。
- **原来的程序有个真问题**：它生成的模板自己读不回来（图会丢、注释和附录会进正文）。这次已经修好，并用 17 项往返测试锁住。
- **推荐做法**：以后模板要二次编辑时，直接 `wechat_md_gui.bat` 打开即可，图注、结论卡、CTA 都会保留；发布前再跑一次体检，图注缺失 / 段落过长 / 加粗过多都会被点名。
